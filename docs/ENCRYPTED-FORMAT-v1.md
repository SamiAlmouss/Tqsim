# Tqsim encrypted format 1 (manifest schema 2)

Schema 1 and unencrypted part bytes remain unchanged. Only explicitly encrypted splits use schema 2 and `encryption.enabled=true`. Unknown format/algorithm/KDF versions are rejected. Absence of schema-2 metadata never makes a legacy archive encrypted.

Legacy schema 1 has no keyed authentication: trust its manifest or an independently held expected SHA-256. Whole replacement with a separately valid legacy archive cannot be cryptographically distinguished from authentic legacy input; preserve trusted manifest copies. Schema-2 field modifications are authenticated, including encryption parameters, but compatibility cannot authenticate historical unkeyed metadata retroactively.

Cipher: .NET AES-256-GCM, 12-byte nonce, fixed 16-byte authentication tag. Password KDF: PBKDF2-HMAC-SHA256, 32-byte random salt, 600,000 iterations, 32-byte master key. Reader resource limit: iterations 600,000–2,000,000; manifest <=16 MiB; <=100,000 parts. Separate AES and manifest keys are HMAC-SHA256(master, UTF8 domain), with domains `Tqsim-GCM-v1 encryption` and `Tqsim-GCM-v1 manifest`. Passwords are UTF-8, without normalization. Argon2id is not packaged; no runtime dependency downloads are required.

Each record is little-endian UInt32 plaintext length, little-endian UInt64 global record ordinal, exactly length ciphertext bytes, and 16 tag bytes. Plaintext lengths are 1..4,194,304. Records never cross physical part boundaries. Record overhead is 28 bytes, so minimum nonempty encrypted part size is 29 bytes. Chunk payload is reduced to fit the remaining physical part capacity. If fewer than 29 bytes remain, start another part; parts need not be exactly the configured maximum. Empty input has zero parts and an authenticated empty plaintext hash.

Nonce = random per-archive 4-byte prefix || global ordinal encoded big-endian UInt64. Ordinals start at zero, increase by one across all parts and may never wrap. A fresh random salt/master key is used for each archive. No record ordinal is reused under an archive key. The conservative per-key record limit is 2^32-1; the maximum ordinal is 2^32-2. Readers and writers reject exhaustion before wrap. This supports nearly 16 PiB with full 4 MiB records.

AAD = ASCII `Tqsim-GCM-v1` followed by a zero byte, .NET Guid.ToByteArray operationId (16 bytes), part index UInt64LE (one based), record ordinal UInt64LE, plaintext length UInt32LE, original size Int64LE, configured maximum physical part size Int64LE. The manifest authenticates final part order, lengths, ciphertext SHA-256, record count, original name/length/SHA-256 and all KDF/layout metadata. Reordering, swapping, truncating and appending records fails authentication/structural validation. Optional verify=false never disables GCM or manifest authentication.

Manifest authentication is HMAC-SHA256 with the separate manifest key over a binary canonical encoding, not JSON property order/whitespace. Encoding: UInt32LE schema=2; length-prefixed UTF-8 applicationVersion; Guid bytes; length-prefixed UTF-8 originalFileName; Int64LE originalSize, partSize, totalParts; raw original SHA-256 (32 bytes); length-prefixed UTF-8 createdUtc; length-prefixed UTF-8 algorithm and KDF identifiers; UInt32LE formatVersion, kdfVersion, iterations, chunkSize, tagSize; raw salt (32 bytes); raw noncePrefix (4 bytes); UInt64LE recordCount; then for each part Int64LE index, length-prefixed UTF-8 fileName, Int64LE size, raw ciphertext SHA-256 (32 bytes). String lengths are UInt32LE byte counts. No BOM or trailing data is included. The resulting authenticator is lowercase hex in encryption.manifestHMAC. Every accepted semantic field is covered; unknown encrypted fields are rejected.

Readers validate bounded structural/KDF fields before derivation, then authenticate this canonical manifest before using its names as paths or allocating data buffers. Decryption authenticates each record before writing its plaintext to a random, owner-restricted temporary file. Full plaintext SHA-256, exact length, part hashes, record order/count and EOF are mandatory before publication. Wrong passwords and modified archives deliberately share an authentication-failure message.

Secure entry uses hidden SecureString input, confirms new passwords, requires 12–1024 characters, and allows long passphrases. CLI password/key parameters do not exist. Mutable UTF-8 password/key/plaintext buffers are cleared when possible. Managed/runtime copies and OS caches cannot be guaranteed erased. Temporary plaintext deletion is best effort, not secure erasure on SSDs, snapshots or journaling filesystems. Filename/size/hash metadata is authenticated but not confidential. There is no password recovery. This new container composition requires independent review before treating it as an externally audited format.

References: [.NET AesGcm](https://learn.microsoft.com/en-us/dotnet/api/system.security.cryptography.aesgcm), [OWASP PBKDF2 work factor](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html#pbkdf2).
